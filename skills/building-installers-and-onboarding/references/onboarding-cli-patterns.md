# In-Tool Onboarding & Workflow Breadcrumb Patterns

Use these patterns during **planning**, **build**, or **post-build remediation** so users never hit a dead end after installing a tool or running `<tool> init`.

## 1. User Journey State Machine

Map every CLI command to the user's current state and the next logical action:

```text
[Uninstalled]
   │  scripts/install.sh (--local | --global | --prefix DIR)
   ▼
[Installed, Uninitialized]
   │  <tool> init [--dir DIR] [--non-interactive]
   ▼
[Initialized Workspace]
   │  <tool> doctor / <tool> validate
   ▼
[Verified Ready]
   │  <tool> run <target> / <tool> build
   ▼
[Active Workflow]
```

If a user runs a late-stage command (e.g. `<tool> run`) before `<tool> init`, catch the missing workspace state and print a one-line recovery hint to `stderr` instead of a stack trace:

```text
error: no <tool>.toml found in current directory.
hint:  run '<tool> init' to bootstrap a workspace, or pass '--config PATH'.
```

## 2. Progressive `Next steps:` Helper in Code

Emit human onboarding hints to `sys.stderr` (never `stdout`, so piped data streams like `<tool> build --json | jq` stay clean), and suppress them when `--quiet` or `--json` is passed:

```python
import sys

def print_next_steps(
    summary: str,
    steps: list[tuple[str, str]],
    *,
    quiet: bool = False,
    json_mode: bool = False,
    stream=sys.stderr,
) -> None:
    """Print completion summary and numbered next-step commands to stderr."""
    if quiet or json_mode:
        return
    print(summary, file=stream)
    print("\nNext steps:", file=stream)
    width = max((len(cmd) for cmd, _ in steps), default=20)
    for idx, (cmd, reason) in enumerate(steps, 1):
        print(f"  {idx}. {cmd:<{width}}  # {reason}", file=stream)
```

### Example: `<tool> init` Implementation

```python
from pathlib import Path
import sys

STARTER_CONFIG = """# Starter configuration generated by '<tool> init'
project = "demo"
output_dir = "output"
"""

def cmd_init(target_dir: Path, force: bool = False, quiet: bool = False) -> int:
    cfg = target_dir / "tool.toml"
    if cfg.exists() and not force:
        print(f"error: {cfg} already exists (use --force to overwrite)", file=sys.stderr)
        print("hint:  run '<tool> doctor' to check your setup or '<tool> guide' for usage.", file=sys.stderr)
        return 1
    target_dir.mkdir(parents=True, exist_ok=True)
    cfg.write_text(STARTER_CONFIG, encoding="utf-8")
    print_next_steps(
        f"Initialized workspace in {cfg}",
        [
            ("<tool> doctor", "verify environment and dependencies"),
            ("<tool> build", "compile starter project into ./output"),
            ("<tool> guide", "read the full step-by-step workflow guide"),
        ],
        quiet=quiet,
    )
    return 0
```

## 3. Built-In `<tool> guide` Subcommand & `--help` Epilog

Include both a short workflow epilog in `--help` and a dedicated `<tool> guide` (or `quickstart`) subcommand that prints the end-to-end bootstrap recipe:

```python
WORKFLOW_EPILOG = """Workflow quickstart:
  1. <tool> init                  Create starter config in current directory
  2. <tool> doctor                Check environment and required tools
  3. <tool> run <input>           Execute the main pipeline
  4. <tool> guide                 Show detailed examples and next steps
"""
```

## 4. Packaged CLI Delegation in `install.sh`

When the project is a packaged CLI (`pyproject.toml`, `Cargo.toml`, `package.json`), map `--local`, `--global`, and `--prefix DIR` in `scripts/install.sh` to the native toolchain so entry points and dependencies are installed properly:

| Ecosystem | `--local` (User Home) | `--global` (System) | `--prefix DIR` (Custom Path) |
|---|---|---|---|
| **Python** | `uv tool install .` or `pip install --user .` | `pip install --prefix /usr/local .` | `pip install --prefix "$DIR" .` |
| **Rust** | `cargo install --path . --root "${XDG_DATA_HOME:-$HOME/.local}"` | `cargo install --path . --root /usr/local` | `cargo install --path . --root "$DIR"` |
| **Node.js** | `npm install --global --prefix "$HOME/.local" .` | `npm install --global --prefix /usr/local .` | `npm install --global --prefix "$DIR" .` |

## 5. Post-Build Remediation Audit Checklist

When remediating an existing repository where users get stuck after install or `init`:

1. **Fresh environment test:** Run `HOME=$(mktemp -d) ./scripts/install.sh --local` and verify it succeeds without root.
2. **Custom prefix & uninstall test:** Run `./scripts/install.sh --prefix "$(mktemp -d)/custom"` followed by `--uninstall` and verify clean exit `0` even when re-run idempotently.
3. **`init` → `run` continuity test:** In an empty directory, run `<tool> init`, then execute the exact command printed under `Next steps: 1.` and `2.`. Both must exit `0` without manual file edits.
4. **Uninitialized guard test:** In an empty directory *without* running `<tool> init`, run the main workflow command and verify it exits nonzero with a `hint: run '<tool> init'` message on `stderr`.
5. **Documentation parity:** Confirm `README.md` and `docs/user-guide/` show the same three install scopes (`--local`, `--global`, `--prefix`) and the same post-`init` workflow commands as the CLI.
